# 空間 n-back 簡易実験

Windows向けのオフラインGUIです。0-backと2-backをそれぞれ**600秒（10分）**実施します。
v1.1.0では、BITalinoの計測をOpenSignalsで行い、本アプリがLSLで生理信号を直接受信します。
**刺激1回ごとの試行終了後、および0-back・2-backそれぞれの課題終了後に、生理信号を自動保存します。LabRecorderは不要です。**

## 起動

**`launch.cmd`をダブルクリック**してください。配布版があれば、Python不要の
`dist/v1.1.0/NBackExperiment/NBackExperiment.exe`が起動します。
このフォルダを移動するときは、exeだけでなく`_internal`を含むフォルダ全体を移動してください。

ソースから起動する場合は、Python 3.10以降とtkinterが必要です。

```powershell
python app.py
```

ソース版で生理信号の受信・LSL送信を使う場合は、同じPythonに導入します。課題のみを行う場合は不要です。

```powershell
python -m pip install -r requirements-optional.txt
```

配布版にはpylslとliblslが含まれます。OpenSignalsは別途用意してください。
旧版の実行ファイルと記録はそのまま残しています。`launch.cmd`は更新版を優先して起動します。

## 実施手順

1. OpenSignalsでBITalinoを設定し、Settings → INTEGRATIONS → Lab Streaming Layerを有効にして、計測を開始します。
2. 本アプリで「OpenSignalsの生理信号を同期受信して自動保存する」を有効にし、「信号を検索」を押します。デバイスのMAC/typeとホスト名を確認して選択してください。
3. 参加者ID、課題順序、保存先を設定します。下側はスクロールできます。初回は「練習する」でルールを確認します。練習は選択した各課題60秒、安静0秒、課題間休憩5秒です。
4. 「本実験を開始」を押すと、信号受信と時計同期を確認してから全画面の説明になります。この時点では課題は始まりません。信号を受信できない場合は開始しません。
5. 準備ができたらEnterを押します。5秒の無音の準備期間、初期値30秒の安静期間を経て、最初の課題が始まります。
6. 一致するときだけSpaceを1回押し、次の応答までにキーを離します。不一致なら押しません。
7. 最初の課題が600秒で終了し、初期値60秒の休憩を挟んで次の説明画面になります。Enterで5秒の準備後、次の課題を600秒実施します。
8. 各試行の生理信号ファイルは試行終了後に順次確定します。全課題が終わると最終データを確定し、実験者向けの結果画面を表示します。その後OpenSignalsの計測を停止してください。

本アプリはOpenSignalsの計測開始・停止ボタンを遠隔操作しません。OpenSignalsを先に計測状態にしておき、
受信した連続信号を、LSL時計で課題の開始・終了に正確に区切る構成です。OpenSignals側でも通常の記録を残せます。
課題だけを試す場合は生理信号の受信チェックを外してください。

課題順序は0→2、2→0、各課題の単独実施から選べます。参加者間で順序を割り付ける場合は実験者が設定してください。
初期値の2課題実施は、安静・休憩・準備を含め21分40秒に、説明画面で待つ時間が加わります。
課題の600秒には、2-backの最初の2試行も含まれます。

| キー | 動作 |
| --- | --- |
| Enter | 説明から準備期間へ進む |
| Space | 一致への応答。実施中の画面変化なし |
| Esc | 実施を中止し、記録済みデータを保存 |
| M | 手動マーカーを記録。実施中の画面変化なし |

計測中の別アプリへの切り替えや最小化は、`focus_lost`として中止します。中断時間を除いて再開する機能はありません。
説明画面では他のアプリへ切り替えられるため、LabRecorderの準備を行えます。

## 課題と初期設定

[参考サイト](https://n-back.studio-age.com/jp/)の「3×3の位置刺激」「N個前と一致したらSpace」という形式を参考に、独自に実装しました。
参考サイトは1〜6-backのトレーニング用です。本ソフトでは0-back、600秒の固定長ブロック、実験記録を追加しています。
**以下の提示時間・ターゲット率は本ソフトの実験用初期値であり、参考サイトの仕様を再現した値ではありません。**

| 項目 | 初期値・仕様 |
| --- | --- |
| 0-back | あらかじめ指定した位置なら反応。初期値は中央（位置5） |
| 2-back | 現在の位置が2試行前と一致したら反応。最初の2試行は記憶のみ・採点対象外 |
| 課題時間 | 各600秒。練習は各60秒 |
| 提示間隔（SOA） | 3000 ms。1000 / 1500 / 2000 / 2500 / 3000 / 4000 / 5000 msから選択 |
| 刺激提示時間 | 500 ms。その後2500 msは固定グリッドと注視点のみ |
| 応答受付 | 刺激のソフトウェア描画完了から、次の試行の予定開始時刻直前まで |
| 試行数 | 初期値で各200試行。2-backは198試行を採点 |
| ターゲット率 | 採点可能試行の30%。整数へ四捨五入し、0-backは60回、2-backは59回 |
| 刺激系列 | シードから生成。同じシード・条件・ブロック番号で再現可能 |
| 誤一致の防止 | 非ターゲットでは、比較対象と同じ位置を生成しない |
| 安静・休憩 | 最初の課題前30秒、課題間60秒。変更可能 |

刺激系列はブロックごとに生成します。2-backでは前ブロックの記憶を引き継ぎません。
応答は1試行につき最初の1回のみ採用します。長押しの自動リピートや2回目以降の押下は無効イベントとして残します。

## 生理計測への画面上の配慮

課題・安静・休憩中は同じ無彩色背景`#808080`、固定3×3グリッド、中央注視点を表示します。
刺激は無彩色`#bfbfbf`、グリッドは`#737373`です。0-backと2-backで色、サイズ、配置、キー応答を共通にしています。
グリッドは360×360画素、セル間隔8画素です。カーソルを隠し、得点・タイマー・進捗・正誤・音・装飾アニメーションを表示しません。
ルール説明は計測区間の外に置き、その切り替えもイベントとして記録します。

これはUIによる余計な刺激を減らす設計です。視覚刺激そのものの影響を完全に排除することはできません。
モニター輝度、表示倍率、観察距離、室内照明を参加者・条件間でそろえてください。
0-backは指定位置の出現頻度が高くなるため、両条件の空間分布まで一致する設計ではありません。

## 生理信号の同期受信と各試行の保存（v1.1.0）

OpenSignalsから送られる数値信号の全チャンネルを受信します。ECGやEDA等のチャンネル名・単位はストリームの
メタデータから読み取り、`physiology/stream.json`に保存します。受信値は変換・フィルタ処理せずそのまま保存します。
複数のデバイスが見つかった場合は実験者が選択してください。途中で別のデバイスへ自動接続することはありません。

| 出力 | 内容・確定タイミング |
| --- | --- |
| physiology/continuous.csv | 説明・準備・安静・課題・休憩を含め、接続中の全受信サンプルを逐次保存 |
| physiology/trials/block_01_trial_0001.csv | 各試行の波形。試行終了後に自動保存。末尾の通信遅延を最大1秒待って確定 |
| 同じ名前の .json | 試行の刺激位置、ターゲット、応答、反応時間、保存件数、欠測の状態 |
| physiology/blocks/block_01_0back.csv | 各10分課題の連続信号。課題終了後に自動確定 |
| physiology/blocks/block_02_2back.csv | 2つ目の課題。番号と条件名は実施順に対応 |
| physiology/segments.csv | 全試行・課題の保存先、サンプル数、期待サンプル数、カバレッジ、ギャップ、quality |
| physiology/summary.json | 全体の件数、ギャップ、保存エラー、不完全区間数 |
| physiology/stream.json | デバイス、ホスト、サンプリング周波数、チャンネル名・単位、LSLのXMLメタデータ |

試行別CSVの時刻範囲は**予定提示時刻を含み、次試行の予定提示時刻を含まない**半開区間です。
これにより隣接する試行でデータが重複しません。`relative_trial_ms`は予定開始基準、`relative_stimulus_ms`は
実際の刺激描画完了基準です。実際の提示時刻は試行JSONと従来の`trials.csv`にも残ります。
中止された最後の試行・課題は、中止時刻までで区切って保存します。提示できなかった試行も状態を付けて保存します。
各課題のファイルは受信中に`.csv.part`へ逐次追記し、終了時に`.csv`へ確定します。

LSLの`time_correction()`を使い、送信元のサンプル時刻をこのPCのLSL時計に対応付けます。
元の時刻`lsl_remote_s`、適用補正`clock_correction_s`、補正後`lsl_local_s`をすべて保存します。
さらにn-backのログと同じ基準の`session_ms`と`unix_ns`を保存します。刺激・キー応答の時刻と対応付けられます。
受信とCSV保存は別スレッドで行い、実施中の参加者画面には受信状況や保存通知を表示しません。

2秒以上の受信停止、LSL切断、時刻の逆行、異常な時刻、保存エラーを検出すると中止して記録済みデータを確定します。
欠けた値を補間したり、完全なデータとして扱ったりはしません。`quality=incomplete`、`gap_count`、
`finalized_after_timeout`等を確認してください。`quality=complete`はサンプル数・時刻範囲の簡易チェックであり、
センサ接触や生理信号の品質を保証するものではありません。受信停止が短くてもギャップは記録します。

初期設定では生理信号の受信が有効です（pylsl導入済みのソース版、または配布exe）。受信信号のサンプリング周波数が
正の値で数値形式のストリームを選んでください。1000 Hz・6チャンネルの場合、連続・試行別・課題別のCSVを保存するため、
20分で数百MB程度の空き容量を用意してください。単位は`stream.json`で確認してください。

## 任意の追加記録：LSLマーカーとLabRecorder

PLUX公式資料によると、OpenSignalsはLSLで**生理信号を送信**できますが、外部アプリのストリームを受信できません。
そのため、本アプリのマーカーをOpenSignalsのTXTへ直接挿入する方式ではありません。
追加でXDFも残したい場合は、OpenSignalsの信号とNBackMarkersをLabRecorderで同時記録できます。
本アプリ内のCSV保存だけなら、この追加設定は不要です。

1. OpenSignalsでBITalinoを設定し、Settings → INTEGRATIONS → Lab Streaming Layerを有効にします。
2. OpenSignalsで計測を開始します。必要ならOpenSignals側でも通常の記録を残します。
3. 本アプリで「追加でLSLマーカーも送出する」を選び、「本実験を開始」を押します。ルール説明で待機してください。
4. LabRecorderでUpdateを押し、OpenSignalsの信号ストリームと**NBackMarkers**の両方を選択します。
5. LabRecorderの保存先を設定し、Startで記録を開始します。信号とマーカー両方を選択したことを確認します。
6. 本アプリへ戻り、Enterを押します。`prepare_start`、`baseline_start/end`、`block_start/end`、
   `stimulus_onset/offset`、`response`等が同じLSL時計系のタイムスタンプ付きで送出されます。
7. 全課題終了後、LabRecorderとOpenSignalsの記録を停止します。本アプリのCSVも保管してください。

マーカーは1チャンネル・不定間隔・文字列形式です。1サンプルがJSONで、`event`、`sequence`、`session_id`、
ブロック番号、試行番号、位置、ターゲット判定等を含みます。ストリームのsource_idはセッション固有です。
LabRecorder開始前の`session_start`等はXDFに入らない場合がありますが、CSVには全イベントが残ります。
本アプリはLabRecorderの記録開始を自動確認しません。

LSLを選択して初期化に失敗した場合は開始を止めます。実施中に送出エラーを検出した場合は中止して保存します。
生理信号の受信・マーカー送出の両方を使わない場合、ネットワーク通信は行いません。
CSVだけでOpenSignalsの記録と比較する場合は、時計の一致と共通イベントの対応を確認してください。
Mキーは課題側の時刻記録のみであり、BITalino側へ電気的トリガーを送信する機能はありません。

公式資料：

- [OpenSignalsのLSL設定と送信専用という制約](https://support.pluxbiosignals.com/knowledge-base/how-do-i-use-the-opensignals-lab-streaming-layer-lsl-feature/)
- [OpenSignalsとLabRecorderの同時記録](https://support.pluxbiosignals.com/knowledge-base/how-do-i-stream-data-through-the-labrecorder-using-opensignals-lsl-feature-and-python/)
- [LabRecorder](https://github.com/labstreaminglayer/App-LabRecorder)
- [pylsl](https://github.com/labstreaminglayer/pylsl)

BITalino実機・OpenSignals・LabRecorderの組み合わせはこの開発環境では未接続のため、実験前に実機で試験記録を確認してください。
合成LSL信号による同期受信・試行別保存・切断検出と、LSLマーカー送受信を検証しています。結果は`VERIFICATION_ja.md`を参照してください。

## 保存されるファイル

保存先は初期値ではアプリと同じフォルダの`results`です。実行ごとに日時・ID・モード・ランダムIDから新規フォルダを作成します。
CSVはUTF-8 BOM付きです。氏名等は求めず、参加者IDは実験者が指定します。

| ファイル | 内容 |
| --- | --- |
| session.json | 条件、シード、色、画面解像度、時刻の基準、状態（running/completed/aborted/error） |
| planned_trials.csv | 未提示分を含む全予定刺激系列。位置は左上から1〜9、中央は5 |
| trials.csv | 提示・未提示・中止の試行、ターゲット、応答、RT、正誤、提示遅延、可視時間 |
| events.csv | 準備・安静・休憩・課題・刺激・応答・中止・手動マーカーの時刻 |
| events.jsonl | 逐次追記されるイベントジャーナル |
| summary.json | ブロックごとのHit、Miss、False alarm、Correct rejection、正答率、平均Hit RT等 |
| physiology/ | 同期受信した生理信号、各試行・各課題のCSV、チャンネル情報、保存状況 |

`hit`はターゲットへの応答、`miss`はターゲットへの無応答、`false_alarm`は非ターゲットへの応答、
`correct_rejection`は非ターゲットへの無応答です。正答率は(Hit + Correct rejection) / 採点試行数です。
`warmup`、`skipped`、`aborted`、`invalid_history`は正答率から除外します。
提示が飛んだ場合、2-backの比較履歴が欠けた後続試行は`invalid_history`になります。

時刻は`perf_counter_ns`を基準に記録し、開始時点のUnix時計との対応から`unix_ns`とUTCのISO時刻を作ります。
`observed_wall_unix_ns`と`wall_clock_delta_ms`には実際のシステム時計も記録し、途中の時計調整を識別できます。
`session_ms`はセッション開始基準、RTは当該刺激の描画完了基準です。LSL送出時は`lsl_timestamp`も残します。

イベントと試行は逐次flushし、段階切り替え・終了時にfsyncします。中止時も記録済みファイルを確定します。
強制終了時は`status=running`のままの可能性があり、最終試行・集計が欠ける場合があります。
その場合も、既存のCSVとJSONLを利用できます。

## タイミングの範囲

予定提示時刻はブロック開始時刻から計算し、コールバック間隔の誤差を累積させない方式です。
600秒の予定終了時刻を過ぎた最初のGUIコールバックで終了するため、実測終了時刻にはOSの遅延が加わります。
予定・実測開始時刻、終了遅延、各刺激の提示遅延・可視時間をログに残します。
提示窓を過ぎた刺激は後からまとめて表示せず`skipped`として記録します。

Tkの描画完了時刻は**ソフトウェア上の時刻**です。画面リフレッシュとの同期や光学的な提示時刻、ハードウェアTTLは保証しません。
刺激に同期した厳密な潜時が必要な解析では、フォトセンサ等で実測するか、専用提示環境へ変更してください。

## 開発・検証

```powershell
python -m unittest -v
python app.py --demo
python verify_physiology.py
```

`--demo`は各12秒、提示間隔600 ms、刺激200 ms、安静・休憩・準備各1秒です。
本実験とは別モードで保存します。単体テストは仮想時計で600秒の進行を検証します。

配布版の再ビルド：

```powershell
python -m pip install --target .build_deps pyinstaller pylsl==1.18.5
python build_windows.py
```

`verify_physiology.py`は実デバイスに接続せず、1000 Hz・6チャンネルの合成LSL信号で保存と受信停止検出を確認します。
